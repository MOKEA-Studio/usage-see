# Usage See — MVP 기획

## 목표

Claude, Gemini, Codex 개인 구독의 **현재 5시간 및 주간 사용 한도**를 한 화면에서 확인한다. 사용자는 각 서비스의 사용량 페이지를 따로 찾아다니지 않고, 어느 한도가 먼저 소진되는지와 언제 초기화되는지 알 수 있어야 한다.

**대상:** 세 서비스를 유료 개인 계정으로 사용하는 개발자. API 종량제 사용량, 조직 관리자 지표, Gemini CLI의 별도 할당량은 첫 버전에서 제외한다.

## 핵심 원칙

- 각 서비스가 화면에 표시한 값만 보여준다. 토큰 수나 메시지 수로 구독 잔여량을 추정하지 않는다.
- 5시간·주간 한도는 서비스별로 따로 표시한다. 서로 다른 한도를 합산하지 않는다.
- 값이 없거나 오래되면 `확인 필요`로 표시한다. 마지막 값을 현재 값처럼 보여주지 않는다.
- 계정 비밀번호, 세션 쿠키, API 키는 수집하거나 서버로 보내지 않는다.

## 1차 제공 기능

| 기능 | 동작 |
| --- | --- |
| 통합 대시보드 | **연결된 서비스의 카드만 표시**. 각 카드에 5시간·주간 사용률 또는 잔여량, 초기화 시각, 마지막 확인 시각 표시 |
| 연결 | 설정 화면에서 서비스를 선택하고, 해당 서비스의 공식 사용량 페이지를 브라우저에서 연 뒤 확장 버튼으로 `현재 페이지 읽기` 실행 |
| 연결 해제 | 설정에서 서비스를 해제하면 대시보드에서 즉시 숨기고 저장된 해당 서비스 스냅샷을 삭제 |
| 데이터 읽기 | 현재 로그인된 페이지의 사용자에게 보이는 텍스트만 읽어 정규화. 사이트별 파서로 분리 |
| 상태 표시 | `정상`, `값 일부 없음`, `로그인 필요`, `페이지 변경`, `오래된 정보` 구분 |
| 바로가기 | 카드에서 해당 서비스의 공식 사용량 페이지 열기 |
| 로컬 저장 | 최근 스냅샷만 브라우저 로컬 저장소에 보관. 사용자가 전체 기록 삭제 가능 |

### 화면 스케치

```text
Usage See                         마지막 확인 14:32

Claude       5시간  72% 사용  ↻ 18:40
             1주    41% 사용  ↻ 화요일 09:00
             [사용량 페이지 열기] [새로 읽기]

Gemini       5시간  확인 필요
             1주    64% 사용  ↻ 월요일 10:00
             [사용량 페이지 열기]

Codex        5시간  35% 사용  ↻ 17:10
             1주    80% 사용  ↻ 금요일 12:00
             [사용량 페이지 열기]

설정: [Claude 연결됨] [Gemini 연결됨] [Codex 연결됨]
```

실제 화면에서 사용률이 공개되지 않고 잔여량만 보이면 원래 단위로 표시한다. 초기화 시각도 확인된 경우에만 표시한다.
아직 연결한 서비스가 하나도 없다면 카드 대신 `서비스를 연결해 사용량을 확인하세요`와 설정 버튼을 표시한다. 연결된 서비스의 수집 실패는 카드를 숨기지 않고 상태를 표시한다.

## 수집 방식

**형태:** Chrome 확장(MV3). 팝업이 대시보드이고, 콘텐츠 스크립트는 사용자가 열어 둔 세 서비스의 공식 사용량 페이지에서만 동작한다. 첫 버전은 사용자가 페이지에서 `현재 페이지 읽기`를 눌러 갱신한다. 자동 로그인이나 비공식 내부 API 호출은 필요하지 않다.

수집 파이프라인: `페이지 텍스트 → 서비스별 파서 → 검증 → 공통 스냅샷 → 로컬 저장소 → 카드`.

파서 구현 전에 실제 개인 계정 화면 3개를 확보하여 다음을 확인한다.

1. 5시간 및 주간 사용률/잔여량이 화면 텍스트로 제공되는가?
2. 초기화 시각이 읽을 수 있는 형태인가?
3. 모델별 한도처럼 복수의 주간 값이 존재하는가?

화면에 없는 수치는 만들지 않는다. 특정 서비스의 값을 읽을 수 없다면 해당 필드는 `확인 필요`와 공식 페이지 링크를 제공한다. 스크린샷 OCR이나 수동 입력은 사용성 검증 후 후속 버전으로 결정한다.

## 데이터 모델

```ts
type Provider = 'claude' | 'gemini' | 'codex';
type Window = 'five_hour' | 'weekly';

type UsageWindow = {
  kind: Window;
  label?: string;             // 예: 모델별 주간 한도
  usedPercent?: number;       // 화면에 표시된 경우에만 0–100
  remainingText?: string;     // 백분율이 없는 경우 원래 단위
  resetsAt?: string;          // ISO 8601; 명확히 파싱된 경우에만
};

type Snapshot = {
  provider: Provider;
  windows: UsageWindow[];
  capturedAt: string;
  sourceUrl: string;
  status: 'ok' | 'partial' | 'login_required' | 'parse_error';
};

type Settings = {
  connectedProviders: Provider[]; // 초기값 []
};
```

## 완료 기준

- 세 서비스의 공식 사용량 화면을 각각 열고 버튼을 누르면, 읽을 수 있는 5시간·주간 값이 대시보드에 나타난다.
- 연결하지 않은 서비스는 대시보드에 나타나지 않는다. 연결 해제 후에는 해당 서비스 기록도 삭제된다.
- 연결된 서비스가 0개면 빈 상태와 연결 버튼이 나타난다.
- 읽을 수 없는 값은 빈칸이나 임의의 0%가 아니라 `확인 필요`로 표시된다.
- 초기화 시각은 사용자의 시간대로 보이고, 원본 화면의 시각과 일치한다.
- 새로 읽기에 실패해도 이전 값이 보존되며, 오래된 값임을 명확히 표시한다.
- 네트워크 탭에서 확장 자체가 계정 정보나 사용량을 외부 서버에 전송하지 않음을 확인한다.

## 구현 순서

1. **실측 검증:** 세 계정의 공식 사용량 화면과 표시 필드 확인. 파서 가능 여부 결정.
2. **확장 뼈대:** MV3 manifest, 팝업, 로컬 저장소, 세 사이트 권한.
3. **수집기:** 서비스별 파서와 결측·오류 처리.
4. **대시보드:** 카드, 진행 바, 초기화 시각, 출처 링크, 마지막 확인 시각.
5. **검수:** 정상·로그인 만료·레이아웃 변경·시간대·오래된 스냅샷 확인.

## 후속 버전 후보

자동 갱신, 한도 임박 알림, 추세 그래프, 메뉴바 앱, 다중 계정, 조직/API 사용량은 첫 버전 사용성 확인 후 결정한다.

## 근거 및 주의점

- [Claude 사용량 설정](https://support.claude.com/en/articles/9797557-usage-limit-best-practices): 5시간 세션과 주간 사용량 진행 표시.
- [Gemini Apps 사용량 한도](https://support.google.com/gemini/answer/16275805?hl=en): 5시간·주간 한도와 공식 Usage 화면.
- [Codex 사용량 안내](https://help.openai.com/en/articles/11369540-using-codex-with-your-chatgpt-plan): 5시간·주간 한도와 Settings/usage dashboard.
- API 종량제 지표는 별개이다. 예를 들어 [Claude Usage and Cost API](https://platform.claude.com/docs/en/manage-claude/usage-cost-api)는 조직의 API 사용량용이며 개인 구독 진행률을 대체하지 않는다.

사이트 화면 구조와 표시 필드는 바뀔 수 있다. 따라서 파서의 실패를 정상 상태로 다루고 원본 화면으로 바로 이동할 수 있게 한다.
